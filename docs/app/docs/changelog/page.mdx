# Changelog

All notable changes to Kyle are documented here.

## 0.2.2 — 2026-04-30

### Added
- Autocorrect for mistyped task names with three modes: `suggest` (default, prints `Did you mean 'build'?`), `off` (plain not-found), `autocorrect` (runs the corrected task with a stderr notice). Configure via `kyle config set autocorrect <mode>`
- Args preserved across autocorrect re-run: `kyle buld --force` runs `build --force`
- Fuzzy tab completion in bash/zsh/fish — `kyle buld<TAB>` now suggests `build` when no prefix match exists
- Install-time prompt for the autocorrect mode in `install.sh` and `install.ps1`

### Safety
- Reserved kyle commands (`upgrade`, `config`, ...) are never auto-targeted
- Ambiguous matches at the best distance fall back to suggest mode regardless of setting
- Damerau-Levenshtein distance ≤ 2 with a 50% match-ratio guard prevents short or distant inputs from matching
- Namespaced inputs match per-segment so segment counts must align (`backed:tst` → `backend:test`, never `backend:build`)

## 0.2.1 — 2026-04-17

### Added
- Transparent task arg passthrough — `kyle ccm-admin --help` etc. no longer need `--` as a separator
- `--dir <task>` escape for invoking namespaces or tasks whose names shadow reserved commands
- Shadow warnings when a discovered namespace or dispatcher sub name collides with a reserved command
- Context-aware TAB completion — `kyle ccm-admin <TAB>` suggests the dispatcher's subcommands
- Grouped `kyle` listing: dispatcher subcommands are grouped by Django app (`[surevoice]`, `[dfs]`, ...) matching `ccm-admin help`
- `--completion-for <task>` hidden flag for shell scripts

### Fixed
- `kyle ccm-admin` (bare) now runs correctly via the `[project.scripts]`-installed script instead of failing with a Python entry-point string
- PDM `{cmd = [...]}` array-style scripts are no longer silently dropped
- Release workflow SHA256SUMS file no longer missing platforms due to artifact filename collisions

## 0.2.0 — 2026-04-16 — Dispatcher Extensions & Shell Completion Overhaul

### Added
- **Dispatcher extension system** — pluggable trait for expanding "dispatcher" tasks (Django manage.py, etc.) into discoverable subcommands
- **Django extension** — auto-detects manage.py and `[project.scripts]` entry points, enumerates management commands as subcommands (`kyle exportxml` instead of `pdm run ccm-admin exportxml`)
- **`[project.scripts]` parsing** — PEP-621 console scripts now recognized as kyle tasks
- **Full resolution cascade** — local tasks → dispatcher subs → namespace tasks → namespace dispatcher subs, with conflict detection and disambiguation syntax
- **`--completion-feed`** — emits the full sorted candidate set for shell completion
- **Rewritten shell completions** (bash/zsh/fish) — consumes the new feed, bash handles `:` word-break correctly
- **`kyle upgrade --status`** — shows recent auto-upgrade activity

### Fixed
- Auto-upgrade no longer blocks every invocation (throttled 24h, background detach, silent log)
- PDM `{cmd = [...]}` array format was silently dropped — now parsed correctly
- Ambiguity errors now show qualified forms instead of just listing namespaces

### Changed
- Explicit local task shadows dispatcher sub with same name
- MCP `list_tasks` enumerates dispatcher subcommands
